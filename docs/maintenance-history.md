## 维护规则

每次修复必须同时完成以下事项：

1. 在本账本增加一条记录，写明症状、根因、保护性不变量和证据。
2. 用户数据事故、真机事故、安全边界或离线发布事故必须增加独立 incident 文档。
3. 任何需要长期遵守的实现约束必须写入 ADR 或架构文档。
4. 至少增加一项能在修复前失败、修复后通过的自动化测试。
5. 涉及 WebView、键盘、文件、字体或原生打包的修复必须保留真机/产物验证步骤。
6. 不得以重写用户 Markdown、降低 TypeScript 严格度、放宽 CSP/权限或删除回归测试换取通过。
7. 发布前执行 [`release-checklist.md`](release-checklist.md)，并记录最终 APK 的版本、签名、
   SHA-256 和目标设备。

### UI-2026-11-04：学习主路径视觉整理

- **现象与原因：** 学习首页、资料列表与设置将普通分组包装成描边圆角容器，资料展开操作进一步嵌套 2×2 卡片；重复说明、较重字重与过小触控区分散了任务层级。
- **调整：** 保留“继续学习”独立对象容器；今日进度、最近资料、资料库与学习设置改用平面分组和分隔线。资料原位展开的四项操作改为平面行，“逐句学习”优先；精简重复说明，保留字幕条件、处理状态、错误提示、密钥约束与删除确认。按钮圆角为 10，继续学习和导入表单容器为 16，相关触控区至少 48 dp。
- **替代证据：** FIX-2026-08-15-003 中的 2×2 操作卡只作为历史实现记录，本次以平面操作行替代；原有单项展开、全部处理入口、来源导航、删除确认及领域调用约束不变，既有测试继续保留。新增 `learning-ui-principles-regression.test.ts`，通过 TypeScript AST 检查声明样式，并检查必要信息与入口。
- **自动化结果：** 2026-11-04 全量 129 个测试文件 / 699 项测试、TypeScript 与 ESLint 通过。新增 4 项 UI 约束测试在修改前失败、修改后通过。
- **待验收：** 自动化样式约束不能证明渲染效果。仍需在原生设备检查窄屏、大字体、长标题、导入面板滚动和展开操作；本次未构建或安装发布包。

### FIX-2026-11-05：Agent 权威状态、授权与投递可靠性

- **实现：** 独立 workspace-scoped Agent 文件存储保存事项、委托、coverage/evidence、run 与 App-inbox outbox；不借用可删库重建的检索数据库。输入校验、不可变快照、revision、串行写与读回验证之后才发布成功。自然语言长期意图先进入草稿，时间/时区和授权须明确确认；候选不自动成为待办。
- **审查发现与根因：** 初版自动备份回退可能撤销排除/暂停；网络提取占住写队列；worker 缺少 scope 与终态可见性；ack 失败可能跳过确认；历史快照重用上传新鲜度校验导致时钟回拨错误。均为本次发布前受控复现，未发现生产数据事故。
- **保护性不变量：** 损坏主文件要求显式恢复，隔离保留所有原始字节，恢复后暂停委托、未处理事项重确认、unknown 不重发；模型提取移出写队列，发布前重验委托版本/状态，暂停不等待网络。worker 只接受精确事项 scope，未授权事项和未确认候选不上传；上传快照时间与实际覆盖可见。结果先在 App 持久化，再幂等 ack，响应未知保持游标可重试，不重跑任务。最近失败运行有固定错误码。连接缓存损坏不回退旧 endpoint，避免把新密钥送到旧服务。
- **运行边界：** 独立 Node 24/SQLite worker 支持时区 daily、租约重启、有限重试、分页与独立 outbox，但本次没有部署。App 只做前台补查，编辑/暂停要同步后才影响远端；未接真实邮箱、消息、日历或系统推送，不声称已检查或已通知。

## 长期不变量

### 用户数据

- 文件系统中的 Markdown 是唯一内容真源。
- 兼容性修复只能改变渲染副本，不能静默改写用户原文。
- 只有经过 repository read-back 验证的内容才能显示为已保存。
- 编辑器模式切换、渲染器重建和预览不得改变文档哈希。

### 编辑器与 WebView

- flush、自动保存和原生回显不得主动模糊 DOM 焦点。
- WebView 不接收文件系统句柄；消息必须带身份和 revision 并经过边界校验。
- CSP、导航拦截、`window.open` 拦截和远程媒体占位不得为兼容性而放宽。
- 公式、Mermaid 和其他富内容必须有输入上限、失败降级和可检查的错误状态。

### 发布

- `app-debug.apk` 仅用于开发；离线验收必须使用 `app-release.apk`。
- release APK 必须在 Metro 映射移除后冷启动。
- KaTeX 字体必须随 DOM bundle 离线打包，不能依赖 CDN 或开发机。
- 覆盖安装前必须确认签名一致；不得为安装方便卸载并清空用户数据。

### 2026-11-05：Agent 表单的保存按钮被 Android 键盘挡住

Android 35 模拟器中，键盘展开后原来固定在屏幕底部的保存按钮只有顶部可见。键盘关闭时保留固定页脚；键盘显示时把同一保存操作移到可滚动表单末尾，使它能在输入期间直接触达。原事项表单已随事项与委托功能退出移动应用。

### 2026-11-06：窄屏同时打开多篇笔记时的标签可达性

标签的内容区参与收缩时，窄屏可能只露出图标和关闭键。标签栏现在为每个标签保留可滚动的宽度，并在选中屏外笔记时把它移入视口。两篇起可通过带数量的叠页图标查看完整列表。列表和标签栏共用原有切换与关闭操作。回归见 [notes-navigation-regression](../tests/unit/app/notes-navigation-regression.test.ts)。

### 2026-11-06：笔记重命名、键盘与打开的标签

编辑器中的空白笔记只有标签身份，尚无可改名的文件。重命名现在会先确认编辑器已刷写，再用工作区的文件创建接口把空白笔记保存到指定路径。同名目标按工作区冲突规则处理。重命名表单绑定原笔记的身份，避免切换标签后将输入提交到另一篇笔记。列表的重命名表单在 Android 键盘展开时上移，并计入安全区偏移。侧栏创建文件夹时，滚动容器把键盘展开期间的确认点击交给按钮。重命名、移动和删除刷新时只更新已打开的标签，保留其他草稿和当前编辑模式。

回归覆盖见 [workspace-browser-commands](../tests/unit/app/workspace-browser-commands.test.ts)、[workspace-state](../tests/unit/app/workspace-state.test.ts) 和 [note-organization-regression](../tests/unit/app/note-organization-regression.test.ts)。

存储故障注入也确认，托管笔记移动文件后，目录索引写入失败会让旧路径失效。仓库现在先读回核对正文，再提交索引，失败后按当前索引恢复路径。见 [重命名索引故障记录](incidents/INC-2026-11-06-note-rename-catalog.md)。

Android 35 模拟器使用临时笔记复测了编辑器空白笔记改名、列表键盘展开时点击保存、侧栏键盘展开时点击创建文件夹，以及移动后读回正文、保留收藏和删除。检查真机时可沿用同一流程，用独立测试笔记核对文件夹、扩展名、正文和标签页数量。

### 2026-11-06：Agent 首页四格按钮的页面入口

四格按钮原先与工作区名称打开同一个全局侧栏，学习、笔记和设置分散在其中。现在四格按钮向上展开三个同宽的圆形按钮，分别直达学习、笔记和设置。工作区名称继续打开工作区侧栏。菜单复用主导航的页面定义与跳转逻辑，选择页面后自动收起。回归见 [primary-navigation-regression](../tests/unit/app/primary-navigation-regression.test.ts)。

### 2026-11-06：统一主页面切换

学习、笔记和设置原先仍使用横排导航，和 Agent 的四格按钮不同。四个主页面和笔记编辑器现共用同一个右下角按钮。每次展开显示当前页以外的三个圆形入口。侧栏保留工作区、文件夹和笔记浏览，移除重复的页面快捷项。原横排选中图标守卫由四格按钮的展开状态与共享圆按钮守卫替代，入口顺序守卫移至新组件。回归见 [primary-navigation-regression](../tests/unit/app/primary-navigation-regression.test.ts)。

### 2026-11-06：编辑器底部同排操作

编辑器的格式工具条原先占用单独一行，展开的切页入口会叠到工具条右侧。现在工具条和固定的四格按钮共用底部一排，格式命令仍在左侧独立横向滚动，页面入口在右侧向上展开。回归见 [primary-navigation-regression](../tests/unit/app/primary-navigation-regression.test.ts)。

### DESIGN-2026-11-06：学习首页与逐句练习

### FIX-2026-11-06：首页接收了隐藏编辑器的 Android 键盘

- 主导航隐藏编辑器时只禁用了触摸。系统仍可能把输入连接保留在 WebView 上，而 React Native 的 `Keyboard.dismiss()` 主要负责 React Native 文本框。
- Android 在编辑器离开前台后阻止其原生子视图获取焦点，并只释放该编辑器已有的输入连接。编辑器保持挂载，重新进入后可点正文继续输入。主导航回归测试保护可见性与输入所有权的关联。
- Android 模拟器覆盖安装调试版后，冷启动 Agent 首页时输入法未显示。打开笔记时输入法由 WebView 接管，随后分别切到 Agent 和学习首页，系统输入目标恢复到 Activity 窗口。再次点进同一笔记时键盘正常弹出。可在真机沿用此流程，并用 `adb shell dumpsys input_method` 核对 `mInputShown` 与 `mServedView`。
