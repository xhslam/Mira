# Mira 移动端去 AI 味 UI 设计规范

> **先让产品成立，再让设计消失。**

本规范用于所有移动端界面。视觉样式不得代替信息结构；用户在任一页面都应立即知道自己在哪里、当前内容是什么，以及下一步可以做什么。

| 维度 | 固定准则                         | 实施约束                                                                                    |
| ---- | -------------------------------- | ------------------------------------------------------------------------------------------- |
| 任务 | 先设计用户要完成的事，再决定界面 | 首页优先呈现继续任务；导入、检索、练习均使用明确动作名称                                    |
| 容器 | 容器不是默认组件                 | 普通列表、设置、导航与信息说明使用平面行与分隔线；仅独立对象、模态层与关键输入区使用容器    |
| 圆角 | 圆角是有限层级                   | 标签 6，按钮与输入 10，独立容器和底部表单 16；圆形图标只在确有识别用途时使用                |
| 间距 | 距离表达关系                     | 使用 4 / 8 / 12 / 16 / 24 / 32 / 40；标题与说明紧邻，区块之间留出 24 或 32                  |
| 排版 | 粗体是稀缺资源                   | 正文为 Regular，行标题为 Medium，区块标题为 Semibold；只有少数关键数值与首要动作可使用 Bold |
| 文案 | 描述事实与动作                   | 使用“导入资料”“继续阅读”“12 句”“上次打开于 2 小时前”；禁止空泛的自我宣传                    |
| 图标 | 图标只承担识别职责               | 若文字已足以表达，移除图标；全局只使用同一套线性图标体系，不使用 emoji 作为界面装饰         |
| 状态 | 反馈明确且就近                   | 加载、完成、警告和错误均出现在触发操作附近，说明状态和可执行的修复动作                      |

## 页面检查顺序

每次改动按“用户任务、信息架构、信息层级、对齐、间距、字体、内容密度、状态、动效、颜色与圆角”的顺序审查。若删除阴影、渐变、装饰图标与圆角后页面无法表达结构，则先修复内容关系，而不是再增加视觉装饰。
