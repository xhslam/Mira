# Mira 双模式智能助手设计

**日期：** 2026-08-15  
**状态：** 用户已确认设计，待实现计划  
**范围：** Mira AI 页内的 Markdown 助手与文字英语陪练，以及英语陪练与 Learning 的双向联动

## 1. 目标

Mira 的 AI 一级入口提供两个严格隔离的模式：

- **Markdown**：读取用户明确授权的笔记，支持创建、修改、续写和润色；所有写入继续走现有 proposal、Diff、用户确认和 verified save 边界。
- **英语陪练**：根据用户输入的生活场景开展循序渐进的文字课程，从 Learning 中精选旧短语和句子自然复现，并在课程结束后让用户确认要保存的正确内容。

英语陪练形成闭环：

```text
Learning 中已确认的表达
  → 选择与新场景匹配的 1–2 条
  → 单步文字教学与情景对话
  → 生成 3–5 条正确内容候选
  → 用户取消、修改或确认
  → 写回逐句练习、词汇复习和后续复现池
```

成功标准是：用户在任何时刻都能看出当前模式、当前教学步骤和下一步动作；英语模式不会接触 Markdown 笔记；课程完成后只留下用户需要记住的正确内容。

## 2. 已确认的产品决策

- AI 页面内部提供 `Markdown / 英语陪练` 两种模式，不把英语陪练作为新的一级导航。
- 模式选择采用类似 DeepSeek 手机版的紧凑双选控件，置于页面顶部视觉正中央；它借用交互形式，不复制 DeepSeek 的品牌视觉。
- 英语陪练第一版以文字聊天为主。用户可以按提示在现实中大声朗读，但应用不声称能够判断发音。
- 英语课程由本地状态机控制，一次只推进一个教学动作，不依赖模型自行遵守“循序渐进”。
- 下一节课在新场景中自然复现 1–2 条旧内容，包括用户保存的具体短语、完整句子和可迁移句型。
- 复现池只包含用户主动收藏、课程卡片确认或标记待练习的正确内容；未经选择的导入语料不进入复现池。
- 课程结束后，AI 推荐 3–5 条正确内容。用户可以取消、修改、补选、标记重点，然后确认保存。
- 不保存用户的错误原句，不把完整聊天写入长期学习库，也不把“出现过”视为“已掌握”。
- 课程进行中临时保存会话以支持崩溃和退出恢复；课程完成并确认卡片后删除原始聊天，只保留结构化学习结果。
- Learning 负责持久化课程卡片、学习表达、逐句练习、词汇复习和练习证据。
- Markdown 和英语陪练可复用 Provider 基础设施，但使用各自的上下文、会话、权限和业务数据。

## 3. 非目标

- 第一版不做语音识别、发音评分、音高分析或自动判定跟读质量。
- 不自动保存 AI 推荐内容。
- 不在英语模式中读取、搜索或修改 Markdown 笔记。
- 不保存完整已完成课程的聊天历史或错误表达档案。
- 不把全部 Learning 数据发送给模型。
- 不新增 Mira 云端账号、同步服务或服务端学习档案。
- 不重构现有媒体学习、字幕、课程和词汇复习主流程。
- 不让模型直接写 SQLite、文件或学习仓库。

## 4. 信息架构与入口

`AiWorkspaceScreen` 演进为模式外壳，但两个子模式保持独立状态：

```text
Mira AI
├── 居中模式选择：Markdown | 英语陪练
├── MarkdownAssistant
│   ├── 笔记上下文
│   ├── 对话与工具
│   └── Proposal / Diff / Apply
└── EnglishCoach
    ├── 场景开始页
    ├── 活跃课程
    ├── 情景对话
    └── 课程卡片确认
```

模式切换只改变可见子树，不转换或共享对话内容。切换到 Markdown 时，未完成英语课程保存为可恢复草稿；切回英语模式继续原阶段。正在进行的 Provider 请求必须先取消或结束，不能把后续事件投递到另一个模式。

两个模式都继续位于现有 AI 底部导航目的地内。Learning 一级入口继续展示保存后的资源、句子、词汇和复习进度，但不承担英语陪练入口。

## 5. 英语课程状态机

### 5.1 状态

```text
scenario_setup
  → lesson_preview
  → teach_expression
  → guided_recall
  → imitation
  → roleplay
  → lesson_review
  → card_review
  → completed
```

另有 `paused`、`provider_failed`、`save_failed` 和 `discarded` 状态。失败状态保留最后一个有效业务状态，重试时从该状态继续，不重复写入学习成果。

### 5.2 阶段规则

#### 场景设置

用户输入一个生活场景。场景足够明确时直接生成课程；只有目标无法判断时才追问一个短问题。

#### 课程预告

只展示场景、一个目标、2–3 个核心表达和预计用时，不展开全部解释。

#### 单句教学

一次只展示一个正确表达、中文含义和至多一个必要词汇说明。回复以一个明确任务结束。

#### 引导回忆

提示用户先大声朗读，再不看原句输入。用户也可以点击“已跟读”继续；该动作只表示用户自报完成，不生成发音结论。

#### 模仿替换

每次只替换一个场景信息，用于验证用户会使用表达，而非只会复制。

#### 错误修复

用户回答错误、不会表达或表示没有理解时：

- 停留在当前阶段；
- 改用更简单的中文说明；
- 提供一个更短的正确示例；
- 只要求重试当前表达；
- 当前会话可以临时显示对照，但错误原句不进入长期数据。

#### 情景对话

Mira 每次只扮演角色说一句。提示级别按 `完整句子 → 关键词 → 无提示` 递减；用户未完成当前轮时不进入下一轮。

#### 自然复现

每节最多选择 1–2 条与当前场景语义相关的旧内容。可以原句复现、短语迁移或句型迁移；没有自然匹配时不强行复现。

#### 课程结束

生成 3–5 条正确候选内容，进入课程卡片确认。完成保存后询问继续下一个相关场景还是结束学习。

### 5.3 每轮硬约束

- 一轮只包含一个教学动作和一个用户任务。
- 用户未完成当前任务时，状态机不允许跳到下一阶段。
- 单次正确不代表掌握。
- 模型只提出阶段决策；本地状态机校验并执行转换。
- 不可解析、越界或与当前状态不一致的模型结果按失败处理，不静默推进。

### 5.4 阶段完成条件

- 课程计划固定包含 2–3 个核心表达。
- 每个表达至少经历一次引导回忆和一次模仿替换，才可进入下一个表达；回答需要简化时继续停留，用户也可以明确选择“暂时跳过”。
- 跳过的表达标记为 `needs_review`，不能记录为完成或熟悉。
- 情景对话默认规划 3 个用户回合，最多 5 个。只有计划内回合已完成、跳过或用户主动结束时，状态机才接受 `finish`。
- 用户可以随时结束课程；只有此前已经完成且内容正确的表达可以进入卡片候选。
- 状态机只接受与当前阶段相邻的 `advance`。模型建议跨阶段、越过未处理表达或提前 `finish` 时，本轮失败并可重试。

## 6. 模型调用与提示词

用户提供的英语教师提示词拆为三个层次：

1. **稳定角色策略**：母语英语教师、理解英语思维、简洁自然、面向零基础、以开口表达为核心。
2. **阶段提示**：只允许生成当前状态所需内容，例如单句教学、模仿题或角色一句话。
3. **本轮上下文**：当前场景、目标表达、最近少量对话、允许复现的表达 ID 和提示级别。

课程计划和回合判断使用经过本地 schema 验证的结构化结果。建议的最小结果包括：

- 用户可见文本；
- 当前目标表达 ID；
- 回合判断：`retry | simplify | stay | advance | finish`；
- 下一提示级别；
- 可选的正确表达候选；
- 不含用户错误原句的练习证据。

若 Provider 不支持原生 structured output，运行时收集文本后按严格 JSON 解析；解析失败时不更新课程状态，并显示可重试错误。任何模型返回都不能直接修改学习数据。

## 7. Learning 数据模型

### 7.1 `EnglishLessonSession`

保存活跃或暂停课程：

- 稳定 session ID、状态和 prompt 版本；
- 场景、目标和课程计划；
- 当前阶段、表达索引和提示级别；
- 本课目标表达 ID；
- 选中的旧表达 ID；
- 临时消息；
- 最后成功回合和更新时间；
- Provider profile ID 与可恢复错误。

临时消息只用于未完成课程恢复。课程保存完成或用户明确丢弃后删除。

### 7.2 `LearningExpression`

统一连接课程卡片、资源句子、词汇和复现池：

- 类型：`word | phrase | sentence`；
- 标准正确英文、规范化去重键和中文含义；
- 必要使用提示；
- 来源：新学、纠正后保存、旧内容复现、用户收藏；
- 来源卡片和可选 Resource/Sentence/Vocabulary 关联；
- 状态：`due | learning | familiar`；
- 下次复习时间；
- 完整提示、关键词提示和独立完成次数；
- 最近出现时间与场景。

标准英文相同且类型相同的内容不重复创建；新增场景更新来源关系和练习证据。

### 7.3 `LessonCard`

课程卡片包含：

- 场景、学习目标和时间；
- 用户确认的 3–5 条表达 ID；
- 每条内容的来源性质和本次完成方式；
- 下一节推荐场景；
- 保存状态和幂等键。

课程卡片不包含错误原句、完整聊天、未确认候选或虚构的发音分数。

### 7.4 `ReplayEvidence`

只记录表达 ID、课程 ID、场景、提示级别、是否完成和时间。它不存储用户错误文本。熟悉度由本地规则根据多次跨场景证据更新，模型不能直接设置“已掌握”。

### 7.5 与现有实体映射

- 完整句子写入或关联 `LearningResource + LearningSentence`，可立即进入逐句练习。
- 单词和短语写入或关联 `VocabularyCard`。
- `LearningExpression` 保存统一复现状态，避免从多个 UI 集合重复猜测。
- 课程卡片引用表达，不复制多份正文。

卡片、表达、资源/词汇映射和练习证据必须在一个本地事务中提交。事务失败时保留 card review 草稿，允许使用稳定幂等键重试，不能产生重复表达或半张卡片。

## 8. 复现选择策略

候选仅来自：

- 课程卡片中确认保存的表达；
- 用户主动收藏的短语和句子；
- 标记为待练习或到期复习的表达。

优先级：

1. 已到复习时间且适合当前场景；
2. 上次依赖完整提示；
3. 用户标记重点；
4. 最近课程中新学；
5. 长时间未使用的熟悉内容。

运行时只向 Provider 发送数量受限的候选 ID、正确文本、含义、必要提示和练习摘要。模型选择的 ID 必须属于本轮授权集合，最多两个。未选择内容和完整 Learning 数据库不进入请求。

## 9. 模式权限与隐私边界

### Markdown 模式

- 沿用当前笔记、手动附加笔记和全工作区搜索授权。
- 所有 mutation 继续生成 proposal 和 Diff，用户确认后才能应用。
- 保留 revision、hash、flush、verified save 和 stale proposal 防护。

### 英语陪练模式

- 工具目录不包含任何 workspace read、search 或 mutation 工具。
- 请求构建器不接受 Markdown document、workspace ID、路径或笔记正文。
- 只读取当前课程和经过筛选的 Learning 表达。
- 使用 `LearningSettings.selectedProviderProfileId`，与 Markdown 会话选择隔离。

自动化测试必须验证：相同设备上即使有打开的敏感笔记，英语 Provider payload 也不包含路径、标题或正文。

## 10. 界面设计

本设计遵循 `mobile-ui-anti-ai-refinement`：先建立任务、信息架构和层级，再使用颜色与圆角；删除装饰后仍能完成任务。

### 10.1 模式选择

- 紧凑双选控件位于顶部视觉正中央。
- 顶部采用三列等宽边界：左操作位、居中模式控件、右操作位，避免左右图标把控件推离中心。
- 选中项使用 `accentSoft` 背景和 `accent` 文字；未选项使用次级文字。
- 控件只负责模式识别，不承担营销说明。

### 10.2 Learning 风格适配

使用当前主题令牌：

- 背景 `#0B0B0F`
- 画布 `#101015`
- 正文 `#F2F2F7`
- 次级文字 `#98989F`
- 分隔线 `rgba(255, 255, 255, 0.13)`
- 强调色 `#0A84FF`
- 按下色 `#0071D8`
- 弱强调背景 `#132B49`

字号基线：

- 页面任务标题：30–34
- 当前核心英文：28–30
- 分区标题：20
- 正文：15–16
- 操作：14–15
- 状态与元数据：11–13
- 底部导航标签：11

文字容器不使用固定高度；必须适配系统 font scale、窄屏换行、键盘、安全区和长英文。粗体只用于页面第一重点、当前核心英文和最终保存动作。

### 10.3 页面层级

#### 开始页

第一重点是“今天练什么？”，主要动作是“开始课程”。推荐场景使用扁平列表和分隔线，不使用推荐 Card、统计 Card 或 AI 营销文案。

#### 课程页

第一重点是当前英文表达。只显示当前阶段所需的翻译、一个必要说明、一个任务和输入区。不提前展示将要复现的表达。

#### 卡片确认页

第一重点是用户要保存的正确表达。候选使用可选择的扁平列表，显示正确英文、中文、来源和完成方式；不使用庆祝页、结果卡片或错误原句。

### 10.4 圆角与间距

- 间距只使用 `4 / 8 / 12 / 16 / 24 / 32 / 40`。
- 模式大容器 12、内部选项 9、输入和主按钮 10–12、选择框 6、普通列表 0。
- Card 仅用于确实独立、可单独操作的对象；本流程的普通信息和候选列表不套 Card。

## 11. 真实状态与异常恢复

- **未配置 Provider**：英语模式显示事实状态和“前往学习 AI 设置”，不创建课程。
- **课程计划生成中**：保留场景输入，显示可取消的处理中状态。
- **模型超时或网络失败**：保留当前阶段和用户输入，允许重试；不重复记录练习证据。
- **模型结果不合法**：不推进状态，显示“这一步没有生成成功，请重试”。
- **用户仍未理解**：保持当前表达，降低说明复杂度，不追加新内容。
- **中途切换模式或离开 App**：保存未完成 session，返回后显示“继续课程”。
- **保存失败**：保持用户选择，主动作变为“重新保存”，展示具体可恢复原因。
- **内容重复**：关联已有表达并追加证据，不新建重复复习项。
- **候选全部取消**：允许结束课程，不创建零表达课程卡片、不写任何学习或分析数据，并清理临时会话。
- **长内容和大字体**：正文可滚动，底部输入或保存动作尊重键盘和安全区，不遮挡候选。

## 12. 测试与验收

### 12.1 单元测试

- 每个课程状态的合法与非法转换。
- 一轮只能推进一个动作。
- `retry`、`simplify` 和失败结果不推进状态。
- 复现候选只来自允许集合且最多两个。
- 无自然匹配时返回空复现集合。
- 表达去重、来源关联和熟悉度本地计算。
- 卡片只包含用户确认的正确内容。
- 已完成课程清除原始消息和错误文本。
- 保存幂等性与事务回滚。
- 模式切换不混合会话或 Provider 事件。

### 12.2 集成测试

- 从 AI 页切换英语模式、创建课程、暂停和恢复。
- Provider 缺失、网络失败、无效 JSON 和取消请求。
- 完成课程后写入 Resource/Sentence、Vocabulary 和 LearningExpression。
- “保存并开始逐句练习”打开正确资源和第一句。
- 保存失败重试不产生重复内容。
- 英语请求 payload 不含工作区路径、标题和笔记正文。
- Markdown 模式原有 proposal、Diff 和 apply 流程不回归。

### 12.3 UI 与真机验证

- Android 常见窄屏和目标真机。
- 系统字体 1.0、1.3 和最大可用级别。
- 键盘打开、长英文换行、长中文说明和多候选滚动。
- 顶部模式控件在左右操作存在时仍保持几何居中。
- 深色主题对比度、禁用态、错误态和选择态清楚。
- 切换底部导航、App 后台恢复和进程重启。
- 执行“删除装饰”测试：去掉阴影、装饰图标、强调色和圆角后，页面仍能表达当前位置、当前任务和下一步。

## 13. 实施边界与顺序

建议按以下依赖顺序规划实现：

1. 课程状态机、结构化模型结果和纯领域测试。
2. LearningExpression、LessonCard、临时 session、迁移和事务。
3. 复现选择与 payload 权限边界。
4. AI 页面模式外壳及居中双选控件。
5. 英语开始页、课程页和卡片确认页。
6. Resource/Sentence、Vocabulary 与逐句练习跳转。
7. 异常恢复、隐私测试、字体缩放和真机验收。

实现不得通过弱化 TypeScript strict、绕过现有 Provider/secret 边界、扩大 Markdown 权限或删除现有回归保护来完成。
