# INC-2026-08-20：短语库误识别与个人资料信息密度问题

**状态：** 已修复，待完整工程验证

## 症状

学习模块曾从句子中以 2–3 词 N-Gram 方式生成“重要短语”候选，并允许这些候选进入同一份词汇卡片集合。该做法会把普通相邻词、残缺语法片段和非复用长句片段误当作短语。与此同时，个人资料入口复用了旧词汇页面，导致短语与长期记忆没有独立的信息结构、搜索、详情和真实删除路径。

## 根因

根因位于 `src/learning/learning-enrichment.ts` 的 `extractImportantPhrases()`：函数仅以 stop-word 和最小长度过滤连续 2–3 词切片，不验证表达边界、语言类型或可复用性。`VocabularyScreen`、练习页和英语课程保存路径也曾分别构造词汇卡，缺少唯一的规范化、置信度和去重入口。

## 影响

历史数据可能包含低质量短语；本次不删除或自动改写任何已有短语。新产生的自动候选改由白名单表达规则、边界验证与 `0.80` 置信度门槛控制。用户显式保存的短语继续以最高优先级写入，但会经过统一规范化和 canonical 去重。新增的 `memories` 集合与 `vocabulary` 分离，旧快照加载时默认初始化为空，保证已有短语保留。

## 保护性不变量

| 不变量                              | 保障措施                                                                                           |
| ----------------------------------- | -------------------------------------------------------------------------------------------------- |
| 自动候选不得由任意 N-Gram 产生      | `phrase-recognition.ts` 仅从可复用表达规则生成候选。                                               |
| 低置信度或不确定候选不得自动落盘    | `shouldAutoSavePhrase()` 统一执行 `MIN_AUTO_SAVE_CONFIDENCE = 0.80` 门槛。                         |
| 同一 canonical 表达不得产生重复卡片 | `upsertPhraseCard()` 按 canonical 文本合并、累计遇到次数并保留有限上下文。                         |
| 用户手动保存不能被算法拒绝          | 所有人工触发路径显式使用 `{ manual: true }`，但仍走同一去重入口。                                  |
| 旧用户短语不得在升级时消失          | `normalizeLearningSnapshot()` 接受 v1–v4 快照，升级到 v5 时保留 `vocabulary` 并初始化 `memories`。 |
| 删除必须写入持久化而非仅隐藏        | 短语与记忆删除均在快照数组中移除，并经学习存储的现有保存链路持久化。                               |

## 修复与验证

修复新增独立的“短语与记忆”页面、短语与记忆两个本地搜索 Tab、详情页、编辑短语与删除路径。短语识别回归测试覆盖 phrasal verb、固定表达、搭配、残片拒绝、canonicalization、重复合并和手动保存例外；快照测试覆盖 v4 到 v5 的非破坏性升级。发布前仍需完成完整测试、静态检查、格式检查和 Android bundle 验证。

## 后续

历史低质量短语保持可见并由用户手动删除；未来若需清理，应提供显式的“审查可疑短语”体验，且必须先展示候选、允许逐条确认，禁止自动破坏性迁移。
